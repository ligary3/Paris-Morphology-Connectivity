# Local data layout

Set `PARIS_DATA_ROOT` to the directory corresponding to the original study's `2/` data folder, and `PARIS_WRF_ROOT` to a local WRF work directory. No drive-letter or username editing is needed in archived Python path constants.

```bash
export PARIS_DATA_ROOT=/path/to/paris-data
export PARIS_WRF_ROOT=/path/to/wrf-work
```

```powershell
$env:PARIS_DATA_ROOT = 'E:\your-paris-data'
$env:PARIS_WRF_ROOT = 'E:\your-wrf-work'
```

Expected external subdirectories retain the study's existing names:

```text
PARIS_DATA_ROOT/
├── 建筑形态/Paris/processed/phase1a_v2/
│   ├── targeted_imputed/
│   ├── urban_mask_100m_v1/
│   ├── real_homo_design_v2/
│   ├── extended_domain_v1/
│   ├── wrf_ucp_d03_v1/
│   └── wrf_activation_pilot_v1/injection_templates/
├── LCZ/Paris/Cerema_2022/
├── 气象观测/Paris_WRF_validation/
└── 空气质量/Paris_2022_event/
```

Some raw-input scripts provide `--raw-gpkg`, `--output-dir` or similar overrides. Python scripts are best run with `codes/run.py`; shell scripts require Bash/Linux or WSL and `PARIS_CODE_ROOT` set to the repository's `codes/` folder. WPS static-geography paths in the namelist must be edited locally.

Processed arrays generated by the full workflow reside under `codes/new_study/` in their original relative stage locations. The distributed small statistical inputs/results are mirrored to those locations where needed by imported control scripts. These mirrors do not include full spatial input datasets or meteorological output fields.

The figure notebook requires these additional products: the morphology reference GeoPackage, real geogrid, Circuit rasters/cell tables, paired transport arrays, WRF surface fields and observations, LCZ grids, and DEM/Natural Earth context layers. Full figure rendering is not possible from the small statistical input arrays alone. Arial is used in the original figures; install it locally or accept a font fallback.
